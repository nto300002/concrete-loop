# Concrete Loop：技術構成 v1

## 位置づけ

本書はD-01〜D-10を実装するための技術構成を定める。技術スタックは維持し、責務境界を明確にする。

> **Reactは操作する。Rustは守る。Pythonは分析する。**

## 全体構成

```text
React UI
React + TypeScript + Vite
Screen / Component / Question Workspace
              ↓
TypeScript Application Layer
UseCase / Query / Mutation / ViewModel
SourcePort / RepositoryPort / AnalysisPort / SecurityPort
       ┌──────┴──────────┐
       ↓                 ↓
Desktop Adapter      Analysis Adapter
Tauri invoke()       Dedicated Web Worker
       ↓                 ↓
Rust Core           Pyodide
Application /       fixed Python / fixed packages /
Domain / Repository analysis only
       ↓
SQLCipher SQLite / Keychain + Touch ID / File System + Backup / Notion Import
```

## Frontend

| 領域 | 採用 |
| --- | --- |
| UI | React + TypeScript + Vite |
| Routing | React Router |
| 非同期の永続データ | TanStack Query |
| 画面内State | `useState` / `useReducer` |
| 限定的な共有UI State | React Context |

DB由来のデータは`SQLite → TanStack Query Cache → UI`で扱う。ZustandやReduxをMVPの前提にせず、DB・Global State・React State・Query Cacheに同じ正本を複製しない。

Viteはtranspileと別に型検査を行う必要があるため、CIまたはbuild手順に`tsc --noEmit`を含める。

React Componentから直接`invoke()`を呼ばない。TypeScript Application LayerのUse CaseとPortを経由する。

```text
Component → createFragment() → FragmentRepository Port
                                   ↓
                         TauriFragmentRepository
```

Web/Desktopで共有するのはReact UI、TypeScript Use Case、View Model、Analysis UI、Domain presentation model、Port interfaceである。DB実装や正本操作まで共有するものではない。

## Desktop Authority Boundary

DesktopはTauri 2 + Rustとし、Tauri CommandはIPC Adapterに留める。

```text
Tauri Command
  ↓
Application Service
  ↓
Domain Rules
  ↓
Repository Trait
  ↓
Infrastructure
```

Rust側の責務分割：

```text
commands/
application/
domain/
repository/
infrastructure/
platform/
```

Frontendは意図を表すRequest DTOだけを送る。Dataset Snapshot作成、immutable条件、Provenance、Evidence、削除規則、Backup、Transaction等のDomain InvariantはRust側で検証・実行する。FrontendがSQLや永続化手順を組み立てない。

## PersistenceとDTO

- Desktop DBはSQLite + SQLCipher、Rust側アクセスは`rusqlite`を第一候補とする。
- Domain → Repository Trait → Sqlite Repository → `rusqlite` → SQLCipherの構造とする。
- Migrationは`rusqlite_migration`を候補とするが、DB Schema詳細設計で最終決定する。
- Rust Domain EntityをUIへ直接公開しない。Rust DTOからTypeScript DTOを生成する方式（`ts-rs`候補）を採用候補とし、Serdeとの名前・型のずれを防ぐ。

## Python分析境界

```text
SQLCipher
  ↓ Rust
DatasetSnapshot DTO
  ↓ Tauri
TypeScript
  ↓ postMessage
Dedicated Web Worker
  ↓
Pyodide
  ↓
AnalysisResult DTO
  ↓ TypeScript → Tauri → Rust
  ↓
SQLCipher
```

Pyodideは`AnalysisPort`の実装であり、Primary DB、SQLCipher、Filesystem、Notion、Keychain、Backup、Tauri API、AI Secretへ直接アクセスしない。Workerには分析に必要なSnapshotだけを渡す。

```json
{
  "columns": [],
  "rows": [],
  "operation": "spearman",
  "parameters": {}
}
```

Pyodide、Python、許可PackageのVersionは固定し、Application Bundle内の`pyodide/`へ同梱する。外部CDN、`micropip.install()`、任意Package取得、自由Python実行を許可しない。MVPのPackageは必要最小限（Pyodide Core、NumPy、pandasを基本）とし、SciPyは具体的分析要件が生じた時点で追加判断する。

## Securityと外部接続

```text
SecurityPort
 ├─ LocalAuthentication → macOS Touch ID
 └─ SecureKeyStore      → macOS Keychain
```

DB KeyをReactへ返さない。ReactはUnlock要求だけを発し、RustがTouch IDを実行し、KeychainからDB Keyを取得してSQLCipherを開く。

Notion接続もFrontendから直接行わない。

```text
React Import要求 → Rust NotionAdapter → KeychainのToken → Notion API
                    ↓
              Normalize → ExternalArtifactVersion → SQLCipher
```

ファイルImportは`FileImportPort → DesktopFileAdapter → Rust filesystem → Parser → ExternalArtifactVersion`とする。MVP対象はTXT、Markdown、JSONである。

## Web版の責務

```text
Web版：Concrete Loop Client / Learning Environment
  ○ UI / Learning / Pyodide分析 / Fileによる限定分析
  × Primary SQLCipher DB / Keychain / Backup SSOT / Desktop Source管理

Desktop版：Concrete Loop Personal Lab本体
```

Web版はDesktop版の完全再現を目指さず、一時的・非正本の状態だけを扱う。
